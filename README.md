# 本地屏译（LocalScreen Translator）

Windows 本地离线屏幕翻译托盘工具：框选截屏、划词、窗口持续翻译、区域实时翻译。文字识别和翻译都在本机完成，不联网。译文可以直接「原位替换」盖在原文位置，保留原文的颜色和字号，效果类似微软电脑管家的截图翻译。界面支持中文和英文。[English](./README.en.md)

![截屏翻译 · 原位替换](docs/images/screenshot-replace.png)

> 本页示例图均由本机 PP-OCRv6 识别、HY-MT1.5-1.8B 模型实际翻译后，用应用自己的界面组件绘制，译文未经人工修改。

## 功能一览

| 功能 | 默认热键 | 显示方式 |
|---|---|---|
| 截屏翻译 | Alt+Q | 原位替换 或 结果窗口（可一键切换） |
| 划词翻译 | Alt+W | 结果窗口 |
| 窗口持续翻译 | Alt+E | 原位替换 |
| 区域实时翻译 | Alt+R | 原位替换 或 字幕条（可一键切换） |

窗口持续翻译和区域实时翻译同一时间只能运行一个。托盘菜单可打开设置、历史、日志和退出。

### 原位替换

- 每行原文位置铺上从周围取样的背景色，再用原文的颜色和字号写译文；背景复杂时改用图像修补。
- 相邻、左对齐、行高和颜色相近的几行合成一段整体翻译，再在原段落范围内自动换行。译文放不下时先收紧行距，再把字号最多缩到原来的 70%，仍放不下才在末尾省略。
- **截屏**：显示截图那一刻的静态画面，外围有白色虚线框。按 `Esc` 或点「关闭」退出。
- **持续翻译**：只盖住文字所在的行，其余部分仍是实时画面；页面滚动后旧译文会立刻撤下，文字移动时译文跟着移动。覆盖层不会被自己的截图识别到，不会重复翻译译文。
- **倾斜与竖排**：倾斜的文字顺着原来的角度盖色块、写译文；竖排中文/日文按从右到左的列合段，译成中日文时译文也竖排，译成英文等拉丁文字时改为旋转后横排。上下颠倒的文字暂不支持。
- 这是屏幕上的覆盖层，不会修改目标程序里的文字。

![倾斜与竖排](docs/images/rotated-vertical.png)

### 控制条

原位替换时，目标区域左上方有一条控制条（区域贴近屏幕顶端时改放在区域内侧）：

| 场景 | 按钮 |
|---|---|
| 截屏原位替换 | ⠿ 拖动 · 目标语言 · 结果窗口 · 对比 · 复制 · 保存 · 关闭 |
| 区域实时翻译 | ⠿ 拖动识别框 · 固定 · 目标语言 · 字幕条 · 对比 · 暂停 · 关闭 |
| 窗口持续翻译 | 目标语言 · 对比 · 暂停 · 关闭 |

- **对比**：按下显示原文，再按一次恢复译文，不会重新翻译。
- **复制**：复制当前看到的内容，显示原文时复制原文，显示译文时复制译文。
- **保存**：把截屏译文保存为 PNG，保持截图原始分辨率。
- **目标语言**：点一下弹出语言菜单，切换后立即重新翻译。
- **快捷切换**：截屏控制条的「结果窗口」与结果窗口里的「原位替换」互相切换；区域控制条的「字幕条」与字幕条上的「原位替换」互相切换。切换后会记住，下次默认使用这种方式。

![区域实时翻译 · 原位替换](docs/images/region-replace.png)

### 结果窗口

截屏切到结果窗口后，原文与译文按段落显示，可以编辑原文后重新翻译、分别复制，按 `Ctrl+Enter` 也能翻译。划词翻译和手动输入翻译也使用这个窗口。

![结果窗口](docs/images/screenshot-result-window.png)

### 字幕条

区域实时翻译可以改用字幕条：译文整段显示在识别区外侧，不遮挡画面，适合视频和游戏。翻译框和识别框各有控制条，可跟随、自由摆放或固定；拖动右下角把手缩放，双击恢复自适应。

![区域实时翻译 · 字幕条](docs/images/region-subtitle.png)

### 其他

- 选择要持续翻译的窗口时，可在搜索框输入标题筛选。
- 框选时有尺寸提示，方便对齐。
- 设置、翻译窗口和字幕条会记住位置和尺寸。
- 翻译历史与本地缓存可在设置或历史窗口中管理和清理。
- 可在设置「常规 → 启动」开启开机自动启动（开机约 30 秒后再加载模型，减轻开机负担）。

## 当前架构

| 环节 | 实现 |
|---|---|
| OCR | PP-OCRv6 ONNX，ONNX Runtime DirectML 优先，不可用时回退 CPU |
| 翻译 | 进程内 llama.cpp v0.5.0，兼容 GGUF 由用户导入（推荐 HY-MT1.5） |
| 显示 | PySide6 托盘、窗口与屏幕覆盖层 |

翻译自动识别原文语种，目标语言可在控制条随时切换。模型与设备设置保存后在后台生效，无需重启。

## 运行条件与准备

- 64 位 Windows。
- 源码运行使用 Python 3.11～3.13，推荐 3.12；构建好的 EXE 与安装包不要求目标电脑安装 Python。
- 翻译 GPU 路线需要兼容的 NVIDIA 驱动；设备选「自动」时可回退 CPU。OCR 使用 DirectML，CPU 可作为回退。

### 方式一：直接下载运行（推荐普通用户）

从 [GitHub Releases](https://github.com/2061863797/LocalScreenTranslator/releases) 获取发布资产：
1. **下载安装包**：下载 `LocalScreenTranslator-Setup.exe` 安装运行（已内置 PP-OCRv6 离线识别模型与 `llama-native` 原生动态库）。
2. **下载翻译模型**：下载 `HY-MT1.5-1.8B-Q4_K_M.gguf`（或其它兼容 GGUF 模型）。
3. **导入并使用**：启动软件后，在「托盘 → 设置 → 高级」中导入该模型文件，保存后即可离线翻译。

### 方式二：源码运行与本地构建

1. **准备运行资源**：
   - 从 GitHub Release 下载 `ocr.zip` 并解压到 `runtime\ocr\`（包含 `manifest.json`、`det.onnx` 等）；
   - 从 GitHub Release 下载 `llama-native.zip` 解压到 `runtime\llama-native\`（或执行 `scripts\fetch_llama_native.ps1` 自动拉取官方 b11146 动态库）。
2. **初始化环境并启动**：

```powershell
.\setup.ps1
venv\Scripts\python.exe scripts\smoke_import.py
venv\Scripts\pythonw.exe run.py
```

3. **本地构建普通 EXE**：

```powershell
.\build-exe.ps1
```

每次构建写入新的 `dist\local-日期时间\LocalScreenTranslator\` 目录，自动集成 `runtime\ocr` 与 `runtime\llama-native`，不覆盖已有 EXE。运行其中的 `LocalScreenTranslator.exe` 即可。

构建脚本还会打印匹配本次输出目录的 `ISCC.exe` 命令。安装 Inno Setup 6 后执行该命令，即可在本次构建目录生成 `LocalScreenTranslator-Setup.exe`。

## 导入翻译模型

在「托盘 → 设置 → 高级」导入兼容 GGUF，可直接引用外部文件或复制进用户模型目录；HY-MT、Qwen、Gemma 需有当前 llama.cpp 可解析的聊天模板。选择模型与 CPU/GPU/自动设备后保存，后台加载。

## 常见问题

| 现象 | 处理 |
|---|---|
| OCR 模型缺失或校验失败 | 将 Release 的 `ocr.zip` 解压到 `runtime` 目录，然后重启应用 |
| AI 模型加载失败 | 检查 GGUF 与聊天模板；在设置中选 CPU 重试 |
| 原位替换遮住了不该遮的内容 | 点控制条上的「对比」查看原文，或把截屏切到「结果窗口」 |
| 上下颠倒的文字识别成乱码 | 暂不支持倒置文字，可先把图片转正再截屏 |
| 数据和日志路径 | 便携模式位于程序根目录，安装版位于 `%LOCALAPPDATA%\LocalScreenTranslator` |
